# 领域资料

## 背景与口径

盐边灾区地面网络中断后，翼龙无人机携空中基站升空组网。后台需要回答指挥员两个问题：

1. 空中基站在任务时段内**实际覆盖了哪些救援点**；
2. 哪些队伍仍处于**通信盲区**，以及他们**最近一次真正的通话**是什么时候。

设备上报的“外部接入尝试次数”（`access_attempt`）**不等于成功通话人数**，系统严格区分：

| 结果 | 定义 |
| --- | --- |
| connected（成功连接） | 链路出现 `call_connected`；`successful_calls` 只以此计数 |
| rejected（明确失败） | 链路出现 `access_rejected` |
| unknown（未知结果） | 查询窗口结束时链路仍无接通/拒绝终局 |
| retry（重复重试） | 同一会话链路中首次尝试之后的 `access_attempt`，单列计数 |

`call_dropped` 表示通话中断，但不抹掉“曾成功接通”的事实；无对应接通记录的中断记为孤立事件，不产生成功通话。没有观测到尝试记录的接通不会反推虚构尝试数。

## 数据范围

- **任务** `missions`：任务时段（`starts_at`/`ends_at`，结束为空表示进行中）。
- **基站与窗口** `stations` / `station_windows`：基站挂在任务下；只有在实际升空服务窗口内，覆盖几何才有效。
- **覆盖区** `coverage_zones`：圆心（纬度/经度）+ 半径（米），可带 `valid_from/valid_to` 随航向调整；判定使用大圆距离（haversine）。
- **队伍与花名册** `teams` / `mission_teams`：编入任务但全程静默的队伍仍会出现在盲区名单。
- **位置上报** `team_locations`：用于覆盖回放，保留设备原始时间。
- **事件流** `events`：只追加，`source_event_id` 幂等。
- **时钟校正台账** `clock_corrections`：见下。

`contracts/entities.json` 保存外部数据交换字段与枚举。来源编号仅表示提交方对同一记录的识别符，示例文件不包含真实个人资料。时间字段使用带时区偏移的 ISO 8601 字符串；存储与查询统一归一化为 UTC。

## 时钟漂移与迟到日志

校正公式：`校正后时间 = 设备原始时间 + offset_ms`。

- 事件与位置同时保存**原始时间串**（永不改写）、**校正后 UTC 时间**、**采用的校正依据 id** 与**实际使用的偏移毫秒数**。
- 校正依据（GNSS 对时、网络对时、人工估计、漂移模型等）可**晚于事件到达**。登记新依据后，同设备历史事件与位置的校正时间按最新依据重算；旧依据标记 `superseded=1` 但保留，可回放当时判断。
- **迟到日志**（事件按设备时间先发生、却晚送达）按校正后时间排序参与关联，不会因接收顺序晚而被错配成失败。
- 查询盲区时，最近一次有效联络同时返回设备原始时间与所用校正依据，供调度员核对。

## 盲区判定

在指定任务时段（缺省取任务整体时段）内**没有任何 `call_connected`** 的队伍进入盲区名单，并附：

- `coverage_at_window_end`：窗口末端覆盖状态——`covered_but_no_call`（在覆盖区内但没打通，区别于真正失联）、`not_covered`、`unknown_position`；
- `access_attempts_in_window`：窗口内接入尝试次数（**仅为尝试，不代表联系上**）；
- `last_effective_contact`：该队伍最近一次真正接通（可早于本时段），含原始时间、基站与时钟依据。
